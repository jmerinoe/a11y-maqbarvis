# Proposal: Metro hotspot curation (designer output)

## Why

The station hotspots on the chromatic metro map were generated by OCR
(`tools/extract-metro-map-svg.mjs`) plus manual overrides. Some landed
imprecisely — offset from the label/tick, or wrongly sized — which makes
station picking unreliable on the real plano.

The hotspot designer (`#/metro-design`, shipped upstream) lets a curator
drag/resize boxes visually. The curated output file has been produced
(`metro-map-data.js`, 108 entries) and must be integrated.

## What changes

- `apps/experience/src/experiences/chromatic/data/metro-map-data.js` is
  replaced by the curated file: **30 stations corrected** (position and/or
  size), the remaining 78 unchanged.
- **One regression in the curated file**: `Campo de las Naciones` (L8) is
  missing — it was dropped during curation. Proposal: re-insert it keeping
  the current known-good position (x≈0.824, y≈0.277) so the model's 109
  stations stay complete.
- No code changes: the map already consumes `stationPositions` generically.

## Out of scope

- Kiosk: untouched.
- Metro model (`metro.js`), screen logic, dialogs: untouched.
- No new tooling: the designer already exists upstream.

## Risks

- If `Campo de las Naciones` was dropped deliberately (e.g. curator decided
  it shouldn't be a hotspot), re-adding it restores it — flag for user
  confirmation.
- Remaining hotspots were verified visually via the designer; spot-check on
  the running app after integration.
